# Passive Skill Tree

## Data (`Scripts/Passives/`)
- `PassiveTree` (ScriptableObject, `Resources/Gameobject/ScriptAbleObject/PassiveTree/PassiveTree.asset`): list of `PassiveNode` = `id` (stable, saved), `displayName`, `type` (Small / Notable / Keystone), `isStart`, `position` (tree pixels, +y up), `links` (undirected, either side), `modifiers` (`StatModifier`, negatives allowed for keystone drawbacks), `description`, `icon` (art inside the node), `frame` (per-node frame/background art; empty = the type template sprite in the GameUI prefab, tinted by state). Both are drawn in the editor canvas. `Neighbors(id)` builds both directions.
- Editor: **Tools > Project-A > Passive Tree Editor** — LMB select / drag move (Snap + grid), Shift+click = link/unlink with selected, RMB = add Small / Notable / Keystone / Start, set Start, change type, delete; MMB or Alt+drag = pan, wheel = zoom, Delete, F = frame. New nodes added while a node is selected are linked to it. Right panel = node fields + Quick Stat presets (+10 Str/Dex/Int, Life, Mana, Adds 2-5 Damage, Damage %, Attack Speed, Move Speed, Area, Mana Regen; replaces the node's stats). "Sample Layout" / `PassiveTreeEditorWindow.FillSample(tree)` = start + 3 branches (Str up, Dex lower-left, Int lower-right) of 5 small -> notable -> 2 small -> keystone, plus a ring linking the branches.

## Runtime
- `PlayerPassives` (on Player, server rules): points = (level - 1) + `bonusPoints`. Start node is free; another start can be chosen only while nothing else is allocated. Allocate = node exists, points left, adjacent to an allocated node. Refund = not the start and the rest stays connected to the start (BFS). `RequestAllocate / RequestRefund / RequestChooseStart / RequestResetAll`. Stats go to `PlayerStats` source `passive`. Saved with `ICharacterService.LoadPassives/SavePassives` (separate from level/EXP). Loaded in `Start` (after `PlayerExperience` loads the level); ids missing from the tree or no longer connected are dropped.
- Race start: a character made in character select has a race; its `CharacterRace.passiveStartNode` is forced as the start (`RaceStartNode`, `CanChooseStart` = false); saves that began elsewhere are reset to it. No race (Play directly in Hideout) = old behavior.
- Attributes: `StatType.Strength / Dexterity / Intelligence` (base 10 each in `PlayerStats`). Str -> +0.5 Life and +0.2% increased Damage each, Dex -> +0.2% increased Attack Speed, Int -> +0.5 Mana (rates are `PlayerStats` fields, derived in `Rebuild`).
- UI: `PassiveTreeWindow` (P): drag background = pan, wheel = zoom around cursor, LMB node = allocate / choose start, RMB = refund, hover = tooltip, Reset (confirm). Node templates per type + line template in the GameUI prefab.

## Choice / Socket nodes
- `PassiveNodeType.Choice`: `PassiveNode.choices` = list of `PassiveChoice` (name + modifiers). The player picks one when allocating (`RequestAllocate(id, choice)`, server checks the index); the node's own `modifiers` always apply too. To change the choice: refund then allocate again. Saved in the passive id list as `"id|choiceIndex"` (plain ids for other nodes; old saves still load). `GetChoice / GetChosen`. Editor: right-click > Add Choice / Type > Choice (seeds +10 Str/Dex/Int choices); `choices` shows in the right panel; included in JSON export/import.
- `PassiveNodeType.Socket`: allocate it (costs a point), then socket a `PassiveGem` (`Items/PassiveGem.cs`, `ItemCategory.PassiveGem`, own inventory tab "Passive") from the bag: `PlayerPassives.RequestSocketGem(nodeId, instanceId)` / `RequestUnsocketGem`. Node stats = node `modifiers` + gem `modifiers` scaled to the gem's level. The gem moves bag <-> node in one transaction (`IInventoryService.SocketPassive / UnsocketPassive / GetPassiveSockets`, stored per owner as `PassiveSocketedGem`). Refund/reset/choose-start or a tree edit that drops the node returns the gem to the bag (`ReleaseOrphanSockets`, run in `Apply`).
- UI (`PassiveTreeWindow`): both types use the Notable template. Click an available Choice node = `PassivePickerPopup` (code-built list popup) of its choices; click an allocated Socket node = popup of Passive Gems in the bag (+ "Remove gem"); socketed gem icon shows on the node. `InventoryWindow` clones the last tab to add the "Passive" tab if the prefab lacks it.
- `PassiveNodeType.FixedChoice`: like Choice, but options come from a shared set — `PassiveTree.choiceSets` (`PassiveChoiceSet` = id + name + choices) referenced by `PassiveNode.choiceSetId`; edit a set once and every Fixed Choice node using it changes. `PassiveTree.ChoicesOf(node)` returns the right list for Choice / Fixed Choice (runtime + UI use it; `PassiveNode.IsChoice` = either type). Editor: right-click > Add Fixed Choice / Type > Fixed Choice, pick the set in the right panel, manage sets in the "Choice Sets" foldout at the bottom (auto-creates an "Attributes" set the first time). JSON export/import include sets.
- Editor: Socket nodes draw as squares; the right panel is resizable (drag the divider between the tree and the panel, width remembered in EditorPrefs).
- Background art: `PassiveTree.backgrounds` (`PassiveBackground`: `art` sprite, `position` / `size` (0 = sprite size) / `rotation` in tree units, `nodeIds`, `requireAll`). Dark (`backgroundDim`) until the listed nodes are allocated (any one, or all with `requireAll`), then bright (`backgroundLit`); empty `nodeIds` = always lit. `PassiveTreeWindow` builds a "Backgrounds" layer behind lines/nodes (no prefab change; colours refresh with the nodes). Editor: toolbar **Art** (show) / **Lit** (preview bright), "Backgrounds" foldout in the right panel with "Add selected node" per background; included in JSON export/import.
- Node defaults (`PassiveTree.styles`, one `PassiveNodeStyle` per `PassiveNodeType`): default `frame` / `icon` / `scale` (size multiplier) and optional state colours (`overrideColors`: locked / available / allocated) used when a node doesn't set its own. Resolved via `PassiveTree.FrameOf / IconOf / StyleOf / ScaleOf`; `PassiveNodeView.Init(node, frame, icon, style)` applies them, `PassiveTreeWindow` applies the scale. Background art colours (`backgroundDim/Lit`) also live on the tree now.
- Editor right panel has two tabs: **Node** (selected node) and **Config** (Node Defaults, Background Art, Backgrounds, Choice Sets, Check Tree = duplicate/empty ids, broken links, no Start, empty Choice / Fixed Choice, backgrounds pointing at missing nodes). Styles/colours are included in JSON export/import.
- Uniform size + shape + colour per type: `PassiveTree.nodeSize` (default 48, same for every type; 0 = keep the prefab template size) × `PassiveNodeStyle.scale` (1 = same). `PassiveNodeStyle.shape` (`PassiveNodeShape`: Circle / Triangle / Square / Pentagon / Hexagon) and `color` (type colour). In the editor the shape and colour are drawn directly; in game a non-circle shape is drawn by `PolygonGraphic` (code mesh, same orientation as the editor: apex up, square axis-aligned) on top of the template background, only when the node has no `frame` sprite. Without `overrideColors` the polygon uses `color` × state brightness (locked 0.35 / available 0.65 / allocated 1); the config tab has a "Use Type Color for states" button that fills the three state colours from `color`. Old styles get default shape/colour once (`configured`). Socket defaults to Square (no longer hardcoded).
- Editor **Art** tab (right panel: Node / Config / Art): Show Art / Preview Lit, dim/lit colours, the Backgrounds list (Select / Add selected node / Remove). Drag on the tree while this tab is open: click an image to select it, drag the body = move, yellow square (bottom-right) = resize (keeps aspect), circle above the image = rotate (Shift = snap 15°). Undo supported; MMB / Alt+drag still pans, wheel zooms.
- Which tree the game uses: `PassiveTree.LoadActive()` = the tree referenced by `PassiveTreeSelection` (`Resources/Gameobject/ScriptAbleObject/PassiveTree/ActivePassiveTree.asset`), falling back to the default `PassiveTree.asset`. Used by `PlayerPassives` (when `tree` is empty), the Tree Editor's initial tree and the character-select builder. Tree Editor toolbar **Use Tree** saves the open tree and points the selection at it (button shows "In Use ✓" when it already is); referencing it from a Resources asset also puts it in builds.
